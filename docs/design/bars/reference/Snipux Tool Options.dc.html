snipux · room to grow

Eleven more features, one more slot

Ellipse, line, dashed, outline, filled, outline-and-filled, pixelate, watermark — added naively that's a dozen new controls and we're back where we started. The way out is to stop treating them as one list. Three moves, all visible in 12a below: shapes collapse into one slot, style becomes per-tool and lives in the popover, and the watermark isn't a tool at all.

1 Shapes are one slot

Rect, ellipse, line and arrow are the same gesture with a different outcome, so they share a slot that shows whichever you used last. A corner notch opens the family; each shape keeps its own key, so R O L A still go straight there. Two new shapes cost zero new slots.

2 Style is per-tool

The popover renders only what the active tool supports — fill and line style for a rect, strength for a redaction, size for text. Nothing is ever visible that can't do anything, and each tool remembers its own settings, so a red dashed box doesn't turn your pen red.

3 The watermark isn't a tool

You don't draw a watermark — it's applied to the whole image, once, and you want to see where it lands. So it's a toggle with its own small popover for position and opacity, and what the mark actually is gets set in Settings, not here.

Eleven features added for no extra width at all — 11a and 12a both measure {{ mBarC }}. Collapsing four shapes into one slot freed a position, and the watermark toggle took it, so the trade came out exactly even. Two slots carry a notch, and a notch always means the same thing: this slot has siblings. Fill is drawn as three tiny rectangles rather than the words outline/filled/both, and filled shapes reuse the stroke colour at 22% so there's never a second colour picker to reconcile. Each tool also keeps its own style — set a dashed red box and your pen is still a 5px acid line.

The popover went on the same diet. The tool name and the word remembered are gone — the lit slot 30px below already says which tool this is, and “remembered” was explaining behaviour rather than showing state. Swatches dropped to one 21px row, fill and line sit side by side as two wells instead of two labelled blocks, and the shortcut crib moved into tooltips where it belongs: a permanent row teaching you three keys is the definition of a control that stops earning its space. Every figure in this section is measured from the live DOM rather than typed, so it can't drift — the badge above reads {{ mPopC }} for whichever tool you have selected right now, against roughly 250 × 160 in your build for exactly the same controls.

The rule that keeps it this size

Worth writing into the tokens as a budget, because the next ten features will ask for room too: the bar holds eight slots and no more. A new feature has to answer which existing slot it joins as a sibling, or which popover section it belongs to, or whether it's really a Settings preference. Nothing gets a slot for being new. Rounded-rect, freehand-polygon, callout bubble, spotlight — all of those are shape siblings. Arrow-head style, corner radius, text weight — all popover. Default watermark and default ink — Settings.

And the order those slots sit in is a gradient of how much the mark changes the image: draw on top (pen, highlighter) → frame and point (shapes) → add content (step, text) → destroy pixels (redact) → remove marks (eraser, then undo and clear). Every removal operation therefore clusters at the right-hand end, and the one irreversible tool sits beside them, far from the accent action at the left — you never fly past Clear ink to reach the pen. Three rules go with it: never reorder by frequency or recency — position is how you find a tool after a week, and a bar that rearranges itself has to be re-read every time; shortcut letters don't influence order, they're mnemonic, not positional; and Settings mirrors this sequence exactly in its “tool the overlay opens with” row, because if the two disagree the one in Settings teaches the wrong map.

snipux · giving the screen back

The room goes to the second row

The bar isn't the problem — the stack is. Two rows plus a hint occupy ~110px directly under the region, and the tray ends up wider than the bar above it, so the bottom of the stack reads as the main object. 11a folds the options into a popover and gets to one row; 11b keeps both rows visible but earns the width back. Both are live — pick a tool, open the options, drag on the shot.
